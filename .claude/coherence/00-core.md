# Coherence Core

## 1. Cohesion と Coherence の違い

**Halliday & Hasan (1976)** によるテクスト言語学の基本軸。

- **Cohesion（結束性 / 言語的結束）**: 接続詞・指示語・語彙繰り返し・代名詞など、**観察可能な言語表面**でテクストを縫う仕組み。「そんな折」「それでも」「これ」「前述の」など
- **Coherence（一貫性 / 意味的一貫性）**: 文章全体の **意味の通り**。読み手が頭の中で「これとあれが結びつく」と理解できるか

両方とも必要。Cohesion だけ高くて Coherence が低いと「接続詞は揃っているのに、なぜそうつながるのか分からない」状態に陥る（AI 下書きで頻発）。逆に Coherence だけ高くて Cohesion が低いと「言いたいことは分かるが、ぶつぶつ切れる」状態に。

レビュー時は **両方の観点で見る**。どちらが弱いかを明示すると、修正方針が見つかりやすい。

## 2. 接続度を測る単位

接続度は要素のあらゆる粒度で測れる。レビュー時は粒度を明示する:

- **章間 / セクション間**: マクロな構造単位（story-structure 寄り）
- **段落間**: 段落 N → 段落 N+1
- **段落内（文間）**: 段落内の文 1 → 文 2
- **文内（句間）**: 一つの文の中の句や節

基本はまず段落間を見て、ワースト箇所が出たら段落内に降りる。abstract のような密度の高い媒体では段落内まで踏み込むことが多い。

## 3. 評価フォーマット: 接続マップ

各遷移に以下を点ける:

- **接続タイプ**: [01-connection-types.md](./01-connection-types.md) から選ぶ（複合可: 「Background + Elaboration」など）
- **接続度スコア**: 0-10
- **接続を支える要素**: 共有語彙・接続詞・指示語・概念の言い換えなど（観察可能なもの）
- **接続を弱める要素**: 飛躍・共有概念の不在・後出し情報・順序逆転など
- **コメント**: 1 行

表形式が読みやすい:

```
| 遷移 | タイプ | スコア | 支える要素 | 弱める要素 | コメント |
| :--- | :--- | :---: | :--- | :--- | :--- |
| 段1→段2 | Background+Elaboration | 7 | 「インフラ屋」→「本職SRE」の語彙反復 | 「インフラ屋」と「ゲームエンジン個人開発」のギャップに橋なし | 越境テーマ前提の戦略的余白 |
| 段2→段3 | Cause-Consequence | 9 | 「そんな折」、「どこに置くか」の完全一致 | ほぼなし | 本文中ベスト |
```

## 4. スコア 0-10 のガイドライン

| スコア | 状態 |
| :---: | :--- |
| 9-10 | 完全に自然。読み手が接続を意識しない |
| 7-8 | 自然。共有要素が複数あり、接続タイプが明示的 |
| 5-6 | 通じる。接続詞や語彙橋はあるが、論理の橋が薄い |
| 3-4 | 詰まる。共有要素が少ない／飛躍がある／後出し |
| 0-2 | 断絶。読者が「なぜここでこの話？」と止まる |

数字は対話のフックとして使う。機械的に算出するものではない。

## 5. 修正アクション 4 種

スコア 5 未満の接続を改善する 4 つの典型アクション:

| アクション | 内容 | 典型例 |
| :--- | :--- | :--- |
| **A. 接続橋を入れる** | 関係を明示する語・句・文を追加 | 「これが成立するのは…だから」「なのに」「── そしてもう一人」 |
| **B. 要素を移動** | 順序を変えて Setup-Payoff を成立させる | 後段の伏線が浮く場合、その情報を後段の直前へ移動 |
| **C. 接続タイプを変える** | 関係性そのものを再設計 | 「のですが」（弱い逆接）→「なのに」（Antithesis 強化） |
| **D. 削除** | 接続できない要素を削る | 浮いた情報を完全に取り除く |

各アクションには **トレードオフ**（その修正で失うもの）を必ず併記する。例: 「A は字数増（+30 字）。トレードオフ: テンポ低下」。

## 6. レビューの基本ループ

1. 文章を段落単位に分解
2. 段落間の接続マップを作成
3. ワースト 3〜5 を特定（[02-symptoms.md](./02-symptoms.md) のカタログから症状名を当てる）
4. 各ワーストに修正アクション（A〜D）と理由・トレードオフを提示
5. ユーザーが選択 → 修正適用
6. 修正後の接続度を再評価（スコアの推移を共有）

詳細フローは [coherence-review Skill](../skills/coherence-review/SKILL.md)。

## 7. 接続度の評価原則

- **観察可能な要素に基づく**: 主観的に「ここ繋がってない感じがする」ではなく、共有語彙・接続詞・指示語・概念呼応など、誰でも確認できる証拠で根拠を示す
- **接続タイプは語彙化する**: [01-connection-types.md](./01-connection-types.md) の語彙を使うと、議論が再現可能になる
- **複合タイプを認める**: 単一接続タイプにこだわらず、「Background + Elaboration」「Concession + Antithesis」のように複合で実態を捉える
- **明示語の有無で接続度が決まらない**: 接続詞があっても意味接続が薄いことも、なくても自然に繋がることもある（[02-symptoms.md](./02-symptoms.md) §5「逆接の乱用」参照）
