# Connection Types

Rhetorical Structure Theory (Mann & Thompson, 1988) およびその後継研究を元にした、文章要素間の **接続タイプ辞書**。レビュー時にこの語彙から接続タイプを選ぶ。

## 1. 因果系

### Cause-Consequence（原因-結果）
- **意味**: A が原因で B が起きる
- **典型的合図**: 「だから」「そのため」「その結果」「したがって」「〜ので」
- **例**: 「リハで Toil を感じた。だから自動化した。」

### Result（結果）
- **意味**: A の結果として B が成立する（行動の帰結）
- **典型的合図**: 「結果」「結果として」「〜になりました」
- **例**: 「同じファイルに収まり、リハの気重さがほどけました。」

### Justify（根拠付け）
- **意味**: B は A を主張する根拠を提供する
- **典型的合図**: 「なぜなら」「というのも」「〜から」「〜だから」
- **例**: 「これが成立するのは、Slidev が Vue 製だから。」

## 2. 対比系

### Contrast（対比）
- **意味**: A と B が並列対比される
- **典型的合図**: 「一方」「対して」「に対して」
- **例**: 「Steiger は JS/TS で動く。一方、Rust にはネイティブの可視性機能がある。」

### Concession（譲歩）
- **意味**: A を認めた上で B を主張
- **典型的合図**: 「〜のですが」「〜にもかかわらず」「とはいえ」「〜けれど」
- **例**: 「Web 由来の架構です。それでも Rust で通用しました。」

### Antithesis（対立提示）
- **意味**: A と B が論理的に矛盾していて、その矛盾自体が主題
- **典型的合図**: 「なのに」「のくせに」「〜のに」
- **例**: 「運用では Toil を削る日課。なのに、自分の登壇では削れていない。」
- **Concession との違い**: Antithesis は矛盾そのものを焦点化する。Concession は譲歩しつつ前進する

## 3. 展開系

### Elaboration（詳述）
- **意味**: B が A の詳細・具体例・補足
- **典型的合図**: 「具体的には」「例えば」「詳しくは」（明示語なしで詳述する場合も多い）
- **例**: 「機械的に決まる決定木。──『どこに置く？』がレイヤー名でわかる。」

### Background（背景）
- **意味**: B を理解するための前提情報を A で提供
- **典型的合図**: 明示語なしが多い（時制や名詞句の配置で示す）
- **例**: 「本職はインフラエンジニア。趣味で Rust を書いています。」

### Restatement（言い換え）
- **意味**: A を別の語彙・抽象度で言い直す
- **典型的合図**: 「つまり」「要するに」「これは…そのものです」
- **例**: 「これは SSOT そのものです。」
- **注意**: 同じ意味を同じ抽象度で繰り返すと冗長。**抽象度を変えて**言い直すと効く（具体 → 抽象、または抽象 → 具体）

## 4. 時間・順序系

### Sequence（順序）
- **意味**: A の後に B が起きる
- **典型的合図**: 「そんな折」「その後」「次に」「やがて」「それから」
- **例**: 「そんな折、気づきます。」

### Condition（条件）
- **意味**: A の条件のもとで B が成立
- **典型的合図**: 「〜なら」「〜のとき」「〜の場合」「〜さえあれば」
- **例**: 「レイヤー名さえあれば、迷子にしません。」

## 5. 解決系

### Solutionhood（問題-解決）
- **意味**: A の問題に対して B が解決
- **典型的合図**: 「やったのは」「解決策は」「対応として」
- **例**: 「二重管理が痛い。やったのは、スピーカーノートに台本を寄せること。」

### Setup-Payoff（伏線-回収）
- **意味**: A で置かれた要素が B で回収される
- **典型的合図**: 明示語なし（語彙呼応・概念呼応）
- **例**: 「本職はSRE。…そんな折、これは Toil じゃないかと気づく。」
- **注意**: Setup の場所と Payoff の距離が遠すぎると、Setup の時点で読者が詰まる。**Payoff までの距離**と **Setup の場所での意味接続**の両方を見る（[02-symptoms.md](./02-symptoms.md) §1「先出し未回収」参照）

## 6. 要約系

### Summary（要約）
- **意味**: B が A 全体を要約・締めくくる
- **典型的合図**: 「本セッションでは」「以上のように」「まとめると」
- **例**: 「本セッションでは、…越境体験を共有します。」

### Conclusion（結論）
- **意味**: A の議論からの結論を B で提示
- **典型的合図**: 「結論として」「したがって」「だから」
- **例**: 「だから、フロントエンド発の架構はゲームエンジンでも通用する。」

## 7. 補足系

### Evidence（証拠）
- **意味**: A の主張に対して B が証拠を提供
- **典型的合図**: 「実際」「事実」「データで言うと」
- **例**: 「FSD は機能した。実際、deep-import 違反は build error で止まった。」

### Concession-Restatement の合わせ技
複合パターン。「A であるが（Concession）、それはつまり B である（Restatement）」のように、譲歩 + 言い換えで主張を補強する。

## 接続タイプを選ぶときのコツ

- **複合タイプも可**: 「Background + Elaboration」「Concession + Antithesis」など、複数タイプの組み合わせで実態を捉える方が正確
- **接続詞だけで判定しない**: 「のですが」が逆接の形でも、意味的には Setup-Payoff のこともある。**支える要素**（共有語彙・概念）も見る
- **明示語の有無で接続度が決まらない**: 明示語があっても意味接続が薄いことも、明示語がなくても自然に繋がることもある
- **疑わしいときは複数候補を併記**: 「Solutionhood or Setup-Payoff」のように。レビューはユーザーとの対話材料
