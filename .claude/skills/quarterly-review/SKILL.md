# Quarterly Review Workflow（四半期棚卸しフロー）

学び資産（retros / playbook / 表記規約 / メモリ）を四半期に 1 回棚卸しするワークフローです。チェックリストの SSOT は [docs/learnings/README.md](../../../docs/learnings/README.md) §5。本スキルはその消化手順と判断のガードレールだけを規定します。

## 起動条件

- 「棚卸しして」「四半期レビュー」「quarterly review」
- 「playbook 見直して」「古くなった学びを整理して」
- 四半期末付近のセッションで学び関連の作業をしているとき（→ 棚卸し時期であることを提案してよい）

## 手順

[README §5 のチェックリスト](../../../docs/learnings/README.md) を上から順に消化する。各項目の判断ガードレール:

### retros の期限処理

- `expires_at` を過ぎたものは `status: archived` に変更。**ファイルは削除しない**（sources の生データポインタとして価値が残る）
- 期限内でも、対象イベントの「次の同種イベント」が終わっていたら再評価を提案

### playbook の陳腐化確認

- 原則ごとに「直近 2 四半期でこの原則を使った実例があるか」を問う。実例が思い当たらない原則は、削除ではなくまずユーザーに確認（使っていないだけか、無効になったのか）
- 陳腐化と判断されたら打消し線 + 理由 1 行、または削除（ユーザー判断）
- frontmatter の `last_reviewed` を更新

### 昇格・昇華の吸い上げ

- 領域別 playbook（[docs/cfp/playbook.md](../../../docs/cfp/playbook.md) 等）から横断 playbook へ昇格できる学びを探す（基準は README §4）
- 構成に効く原則で安定したものは [.claude/storytelling/90-principles.md](../../storytelling/90-principles.md) への昇華を提案（相互リンク必須）

### 仮説の生死判断

- 各 active retro の「次に試したい仮説」チェックボックスを一覧化し、未検証のものを「続行 / 破棄 / 次イベントで検証」に振り分ける（ユーザーと一緒に）

### 規約・メモリの整合

- この四半期のフィードバックで [rules/17-writing-style.md](../../rules/17-writing-style.md) に未記載のものがないかユーザーに確認
- エージェントのローカルメモリを一覧し、リポジトリに SSOT がない学びが実体としてメモリ側にあれば、リポジトリへ移してメモリはポインタ化する

### 機械チェック

- `just check-content` を実行し、違反があれば修正するか免除リスト行きかをユーザーと判断

### クローズ

- 変更を 1 コミットにまとめて提案（`docs(learnings): 四半期棚卸し YYYY-Q<n>`）
- 次回棚卸し時期（次の四半期末）を最後に一言残す

## 振る舞いの注意

- **一括で黙って処理しない。** 削除・打消し・破棄の判断は必ずユーザーに選ばせる（項目を 2〜3 個ずつ提示するテンポは novel-revision / slop-review と同じ流儀）
- **棚卸しで新しい学びを書き足さない。** ここは整理の場。新しい気づきが出てきたら retro か playbook への通常フローに回す
- 全項目を 1 セッションで終える必要はない。中断するときは残チェックリストをそのまま提示して終わる
