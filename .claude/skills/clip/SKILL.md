# Clip Workflow（外部記事の取り込みフロー）

外部記事と「わたしとの関連」をセットにして [content-private/clippings/](../../../content-private/clippings/) に蓄積するワークフローです。ファイル規約・テンプレの SSOT は [clippings/README.md](../../../content-private/clippings/README.md)。本スキルは取り込みの段取りだけを規定します。

## 起動条件

- 「クリップして」「これ残しておきたい」「素材として取っておきたい」+ URL
- 記事の内容確認（WebFetch）の流れから「あとで使いたい」「蓄積したい」という発言
- URL がなく本文の貼り付け・口頭要約でも成立する（`url` を空にせず出典をユーザーに確認する）

## 手順（チェックリスト）

### 1. 記事の取得と要約

- [ ] WebFetch で記事を取得し、タイトル・著者・要点を把握する（会話内で取得済みなら再利用）
- [ ] 取得できない場合（有料・ログイン必須等）はユーザーに本文または要点の貼り付けを依頼する
- [ ] 同じ URL のクリップが既にないか [clippings/](../../../content-private/clippings/) を Grep で確認する（あれば新規作成でなく追記を提案）

### 2. 関連性の仮説を下書きする（リポジトリから）

ユーザーに聞く前に、以下を読んで「わたしとの関連」の仮説を自分で組み立てる:

- [content-private/about-sakai-nako/](../../../content-private/about-sakai-nako/) — 最新日付の self-portrait と swot-analysis（価値観・強み・関心の軸）
- [src/content/about/profile.md](../../../src/content/about/profile.md) — 公開プロフィール（活動・登壇の軸）
- [clippings/README.md](../../../content-private/clippings/README.md) の一覧 — テーマが近い既存クリップ（あれば「〜のクリップと同系統」と接続できる）
- 進行中のアウトプット — [src/content/cfp/](../../../src/content/cfp/)（応募中・準備中の CfP）、[src/content/novels/](../../../src/content/novels/)（連載中の作品）、[content-external/articles/](../../../content-external/articles/)（記事下書き）

全部を毎回精読する必要はない。記事のテーマから当たりをつけて 2〜3 ファイル読めば十分。

### 3. 確認（1 往復だけ）

要約を 3〜5 行で示し、関連の仮説を **2〜3 個、根拠（どのドキュメント・どの活動と繋がるか）付き**で提示したうえで、聞くことは 1 メッセージにまとめる:

1. 仮説のどれが当たり？（外れ・補足があれば一言で。全部そのままでよければ「OK」で済む）
2. 使うならどの媒体？（blog / slide / novel / sns / cfp。まだ決まらないなら空でよい）

- **採用された仮説だけを「わたしとの関連」に書く。** ユーザーの確認を経ていない推測をファイルに残さない
- ユーザーが自分の言葉で語り直したら**そちらを正**とし、仮説は下敷きに使わず捨てる
- 仮説が全部外れだったときだけ、従来どおり聞く（どこが一番刺さった？ 自分の何と繋がる？）
- 回答が短くても、そのまま活かす（膨らませすぎない）。言葉の整形はしてよいが、ユーザーが言っていない接続を創作しない

### 4. ファイル生成

- [ ] `content-private/clippings/YYYY-MM-DD_<slug>.md` を README のテンプレどおりに作成
- [ ] 「記事の要点」は要約 + 短い引用まで。**全文転載しない**（著作権への配慮）
- [ ] 「わたしとの関連」に確認済みの仮説とユーザーの補足を反映。「アウトプットの種」は出た分だけ（無理に埋めない）
- [ ] [clippings/README.md](../../../content-private/clippings/README.md) の一覧に 1 行追記（新しいものが上。関連の一言フック付き）

### 5. クローズ

- [ ] コミットを提案する（例: `docs(clippings): 「<タイトル>」をクリップ`）

## 活用側（取り込み後の接続）

- 構成づくり（[story-structure Skill](../story-structure/SKILL.md) フェーズ 3 素材出し）や媒体別 SubAgent（blog / slide / novel-architect）が素材を探すとき、このディレクトリを検索する
- アウトプットに使ったら該当クリップの `used_in` に成果物へのパスを追記する
- 四半期棚卸し（[quarterly-review Skill](../quarterly-review/SKILL.md)）で `used_in` が空のクリップを見返す

## 振る舞いの注意

- **確認は 1 往復で止める。** 尋問にしない。ユーザーが「OK」の一言で済ませたいときはそれで完成とする
- **仮説の質は読み込みの質。** 自己分析・既存クリップを読まずに一般論で仮説をでっち上げない — それをするくらいなら従来どおり聞く
- **content-private/ 配下なので作業日付は書いてよい**（[rules/16-content-locations.md](../../rules/16-content-locations.md) §4 の対象外）
- クリップの中身をサイト公開コンテンツへ転記する際は、各媒体の規約（ベタ詰め等）がそちらで適用される — クリップ自体は自由に書いてよい
